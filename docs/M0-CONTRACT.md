# M0 执行与验收契约

Mac 主应用的提醒事项互操作单独按[提醒事项方案](MAC-REMINDERS.md)验收。原生双端 CloudKit 任务库仍按下方矩阵验证。

## 当前范围

M0 验证原生个人任务在 Mac／iPhone 上的捕获、编辑、日期安排、系统 Widget 与安全同步闭环。先推进 Mac 不取消双端门槛；只有 A／B／C／D 必需矩阵与决策冻结全部通过，才可称 M0 完成。当前唯一持久化实现为共享 Core Data／TaskStore，云配置采用 CloudKit 私有库与系统 Apple 账户，不另建应用账号密码体系。

任务语义、平台导航和 Widget 布局见 [产品与界面设计](PRODUCT-DESIGN.md)。M0 不扩展分享扩展、提醒／重复、全局快捷键、完整清单分类、附件／子任务、地图／参会人／外部日历、生产云发布或两周试用。

已授权的 Mac 本机公开交付是独立范围，不代替 M0 云与双端验收：配置／scheme 见[开发说明](DEVELOPMENT.md#配置与-scheme)，MacDistribution 单库、权限、受控旧 Local 升级及系统验收见 [Mac 分发说明](MAC-DISTRIBUTION.md)，同候选构建、草稿与公开流程见[发布说明](RELEASING.md)。不再维护另一套升级或发布步骤。

全部自动运行使用新 `-M0Run` 隔离空间，不触碰个人任务库或手工库；Development、本机与各账户分库，Production 不启用。设备、账户、能力授权或人工条件缺失时明确待验，不以编译或模拟器替代真实设备结果。

## 数据规则

以下是实现必须保持、并须经设备矩阵确认的约束，不是已全部通过的声明。主要入口为 [TaskStore](../Shared/TaskStore.swift)、[StoreSession](../Shared/StoreSession.swift) 与 [TaskIntents](../Shared/TaskIntents.swift)。

- **唯一事实源与提交**：所有任务入口复用 TaskStore，本机事务提交后才反馈成功；业务 UUID 幂等，只更新实际修改字段。标题、初始正文／格式及计划在同一事务创建，不另建可写快照。完成动作设置目标状态，重复完成不反转，但不能据此声称已做请求去重。
- **正文分支**：正文及格式追加不可变版本，保留版本 UUID、父 ID 和全部分支，版本指针不是唯一备份；恢复旧文字也追加版本。仅改标题不能把旧正文写成新远端头，不逐字产生已提交版本。
- **删除与重复记录**：删除采用 tombstone，普通编辑不得清除或复活；恢复须显式操作，不自动清理任务、正文或历史。同任务 UUID 的物理重复按随记录同步的 `recordKey` 稳定选主，只展示一个业务任务；任一副本 tombstone 生效，写动作更新全部副本。不按标题去重，不假设 CloudKit 有 unique constraint。正文按版本 UUID 归并，同版本 UUID 的文字、格式或父关系不同则保留原记录并报错；物理清理须另有同步证据与迁移设计。
- **原子计划**：类型、起止、时区等计划信息存为一个 JSON 标量，本机写入与远端读回均校验，避免字段合并拼出反转／混合区间。并发改期允许选取一个完整有效计划，不承诺保留两个日期意图；真机必须验证。日期使用半开区间，界面结束日包含当天；零点、跨周／年与夏令时按共享规则。`week` 是该周待安排，不占七天全天日程；安排到具体日修改原 UUID，不复制任务。新增编码不承诺旧二进制可读，读失败保留原库；既有计划、旧草稿与备份须兼容。
- **本机草稿**：原子文件属于设备／账户命名空间，保留任务 ID、草稿 ID、基线父版本、文字、格式及捕获计划；不是另一套任务事实源，不跨账户自动迁移。重启可恢复；捕获复用草稿业务 UUID，正文保存以同草稿 ID 幂等追加，事务成功后再清理，清理失败保留并按 UUID 核对。远端不替换输入中草稿，关闭详情前核实落盘；失败保留编辑器与错误，旧详情不能向新库写入。
- **账户门禁**：云开关首次默认关闭；开启只进入系统确认账户的独立云库，关闭回独立本机任务库，各库与草稿保留、不自动上传或搬运。身份未知不把旧库接到镜像，可继续使用明确标示的独立本机任务库，不能伪装为空云库或同步成功。切账户先阻断扩展、关闭旧库；扩展写前重核身份与会话。健康且未变的账户检查不反复重建镜像；无云能力配置不提供无效开关。
- **进程与模型**：主应用负责建库／迁移，且是每台设备唯一 CloudKit 镜像所有者；扩展不建库、不迁移、不镜像，只打开已核验的现有库，独立消费历史。共享会话、模型租约及写锁均保留；时间线绑定命名空间，切库旧动作、缺库、账户未知／变化或模型不兼容均拒写并提示打开主应用。模型版本进入工程、导出与证据；启动／迁移失败保留原库和草稿，不删库重建、不静默落入默认库。
- **Widget 读安全**：读取本机已确认的安全数据，不等待云端交换；身份未知隐藏任务并提示打开应用，读取失败不假装空任务。当前云会话仍需身份查询，其在线／离线渲染边界待实测，不能为缩短等待而绕过门禁，也不能将此路径冻结为已通过；本机配置不套用云身份查询。
- **迁移与恢复**：最低验证包括两个独立容器访问同一隔离库、写锁争用可见失败且无部分提交、扩展遇缺库／不兼容模型保留文件并拒绝建库写入；真实扩展启动与主应用升级相遇仍需设备验证。保留既有模型版本、旧纯文本兼容与主应用升级路径。任务 JSON 从一致读取视图导出，拒绝不完整备份；恢复仅限空的隔离本地库，禁止默认覆盖同 ID 或恢复到镜像／扩展。任务 JSON 不包含完整物理记录身份、草稿与历史，不能代替完整旧库升级；受控升级遵守 Mac 分发说明的原子提交与交换后不回拷规则。
- **隐私**：不宣称天然端到端加密。日志只记录动作／对象 ID、进程、耗时与错误类别，不记录标题、正文或账户原始标识；导出与截图只用合成隔离数据。私有绝对路径、个人签名值、原始测试标识、数据库和原型截图不进入公开文档。

## A／B／C／D 必需矩阵

### A 捕获、编辑与同步

工程自检：[TaskStoreTests](../Tests/TaskStoreTests.swift) 覆盖提交、草稿重启、分支、重复记录、并发改期、删除、备份恢复及门禁。必需运行：

1. 真实 iPhone 断网创建任务，退出／重启核对 UUID、标题与草稿。
2. 恢复网络，真实 Mac 收到同 UUID；补正文与安排日期，手机读回。正常网络且两端前台至少各完成一次双向修改。
3. 双端离线基于同一父正文保存不同文字，并分别修改不同字段；联网后两端均保留分支且可恢复。基于旧快照并发改期须得到完整有效计划。
4. 一端回收，另一端提交旧编辑，普通编辑不得复活；显式恢复单独验证。
5. 验证账户未知、无账户、切换及云开关的库位置／门禁；旧库与草稿不得上传新账户。导出并恢复到新空隔离本地库，逐字段核对。

通过标准：本机重启不丢失、最终一致、全部正文分支可恢复、错误可见、账户隔离。证据包含双端系统、构建／模型版本、动作 UUID、网络与时间线、两端导出及日志；单端导出不等于另一端收到。

### B Mac 月历

工程自检：[SchedulingTests](../Tests/SchedulingTests.swift)、[CalendarPlanningTests](../Tests/CalendarPlanningTests.swift) 与 [WeekTaskOverviewTests](../Tests/WeekTaskOverviewTests.swift)。必需原生运行：

1. 固定样例覆盖上月跨入、跨周／年、零点结束、同日满格及未安排；核对周一开始、标题、跨周条、每天不同任务的 `+N`。任务点击定位原 UUID，日期／溢出打开当天完整任务并能定位原项。
2. 在待办详情为未安排任务设置日期，拖动周待安排任务及跨日条到新日期，整条开始日对齐落点，保持 UUID 与原跨度，截止日期不参与移动；重启复核持久化。
3. 连续翻月、选择与拖动，核对文字可读、响应与空间不足时的浏览；保存原生窗口、操作、导出和可获得的性能观察。

算法测试不代替真实手势、布局和响应证据；固定样例不等于大数据性能验收。

### C 系统 Widget

工程自检为共享库／锁／门禁集成测试与相应配置编译。必须在真实 iPhone 与 Mac 各安装系统 Widget，分别覆盖主应用前台、后台／关窗仍运行、真正退出：

1. 从同设备共享库显示隔离任务；系统 gallery、实际放置及点击分别留证，不以 App 预览代替系统宿主。
2. 点击完成并连点，数据库只设置目标状态、不反转；记录 Intent 的真实进程／PID、动作 ID、本机提交、Widget／App 显示及另一端到达。
3. 主应用退出时先验扩展本地提交，再开主应用验云传播；若不能退出后独立传播，必须可见提示“已保存本机，打开应用后同步”，且在冻结中明确此边界。
4. 已删除任务、旧时间线／切库、账户未知或变化、缺库及模型不兼容均不得误写、建空库或迁移；身份查询和离线本地渲染单独观察。

当前候选是普通 AppIntent 在扩展写共享库、主应用唯一镜像。**SDK／系统 27 的 `allowedExecutionTargets` 主应用执行目标比较仍待验**；环境版本变化不自动视为完成，不凭旧 SDK 限制断言新路径不可用，也不借用无实际 Live Activity 业务的协议强制进程。

| 观察 | 判定与动作 |
|---|---|
| 本机提交／显示、主应用运行时传播正确；退出仅本机保存且提示可见，重启后最终一致 | 可接受候选，不承诺退出后立即跨端；真实双端记录与执行目标比较完成后才冻结 |
| 只有动画未提交、重复反转、过期无提示、主应用运行后仍停滞 | 本轮失败，修复既定路径并重跑，不降低标准 |
| 丢正文分支、跨账户上传、模型不匹配仍写入、迁移失败删库 | 安全失败，保留证据与原库，停止危险路径，先修复 |
| 定位后确认共享写入／镜像调度仍无法满足，或用户明确要求退出后自动传播且支持的主应用执行路径仍失败 | 定向比较 SwiftData／SQLiteData 或同步方案；用相同隔离样例与步骤，最终只留一个正式实现，不因环境缺失或单次慢同步泛化换栈 |

### D 双端运行与系统接入

1. 用 `Todo.xcodeproj` 与共享 schemes 重复构建两端主应用／Widget，执行项目测试；命令见[检查与构建](DEVELOPMENT.md#检查与构建)。
2. 云矩阵使用同一有效开发团队、独立 M0 CloudKit Development 容器与 App Group，真实签名安装两端应用／扩展，核对能力与权限。MacDistribution 的无团队本机交付按独立文档验，不代替云权限或套用团队前提。
3. 两端核对安装、冷启、重启保留、系统 gallery、能力授权；记录 OS／SDK／Swift／Xcode／设备、包与模型版本、实际签名方法及应用／容器／共享组配置。敏感原值只留私有证据。
4. 部署下限、编译范围和实测支持矩阵分开；Personal Team 的 Local 真机运行不证明云能力，无签名编译不证明设备权限。两台真实设备均运行且相应权限可用才通过。

## 冻结与证据准则

| 冻结项 | 必需依据 |
|---|---|
| 唯一持久化 | A／C 的真实离线冲突、共享写入、账户隔离与导出恢复；缺口先定位，再按 C 的触发条件定向比较，不并行维护多套正式实现 |
| Widget 执行与同步 | C 的全运行状态矩阵、PID、传播时间线及 SDK 27 执行目标比较；明确可接受的退出后仅本机保存边界，否则保持候选 |
| 数据安全 | 测试与 A／C 的重启、删除、模型／账户门禁；不得删库恢复、跨账户自动搬运或静默覆盖正文 |
| 支持矩阵 | D 的真实系统、包与必需 API 证据；无设备证据的编译下限只称候选，不扩大支持结论 |
| 签名与能力 | D 的团队、provisioning、entitlement 与实际容器安装核对；示例标识不代表已注册，无签名编译不触发冻结；无团队 Mac 包按其独立权限证据判断 |

### 同步与性能

- 以提交动作 UUID 关联 **T0 本机事务提交 → T1 Widget 读取并显示 → T2 本设备对应 CloudKit 导出事件 → T3 另一设备导入／读取同 UUID**。分别记录，不把 T2 当 T3；系统导出事件也不证明逐任务成功，须结合 UUID、字段与远端读回。
- 正常网络双向前台样例之外，分别记录离线和主应用退出。固定 **10 分钟观察窗**未到达即记“本轮未通过／待定位”，保存网络、账户及全部事件，分清未导出、未导入、已导入但 UI 未更新；无设备记“未开始观察”。这不是系统固定 SLA。
- 本地保存目标 **P95 ≤ 100 ms**，Widget 本地写入目标 **≤ 1 秒**。从业务写入／锁定前至持久化 `save` 返回计时，UI 反馈、系统 Widget 刷新另计。记录设备／OS、冷热、数据量、样本数、原始耗时、网络和构建配置，给出中位数、P95、最大值，不混合条件求分位数。
- M0 先留关键路径基线；50 次前台传播分布及 10,000 条历史／500 活跃任务的大数据性能是后续验收，不能用固定月历样例或少数快样本代替。

### 留证与维护

每次检查记录真实命令、退出状态、源码提交与逐文件 SHA256、日志 SHA256，以及包／资产、系统、模型和隔离空间。源码在检查期间变化不能记为稳定版本；不同源码、配置、签名包和阶段不得拼成一次完整验收。最终发行绑定同一候选 manifest／归档散列，公开不得重建、重签或重传替代资产。

构建、XCTest、签名、原生 GUI、模拟器、物理 iPhone、系统 Widget 和云传播分别记结论。原生 GUI 须有实际操作、截图与数据读回；当前没有 XCUITest 目标，GUI 记录不计入 XCTest 数量。刷新请求、动画、App 预览、单进程测试和双架构编译都不是系统运行证明。

报告、原始日志、`.xcresult`、合成截图与导出留在被忽略的 `.build/`；交接时说明材料是否实际随交付保留。成功、失败与被后续修复的旧记录均保持原义，修复补新证据，不覆盖失败历史。公开页只写脱敏摘要和覆盖边界，不用不可访问的私有路径作依赖。

日志格式 2：`actionID` 是一次业务动作，`subjectID` 是任务／正文版本，`eventID` 是日志行；事务作者带进程和动作 ID，Intent 成功复用动作 ID，CloudKit 开始／结束按系统事件 UUID 关联。历史格式 1 的 `actionID` 是业务对象 ID，保留并注明，不与格式 2 混读。

后续将新证据的身份、实际覆盖、待验条件与下一步集中更新本契约下节；Mac 同资产结果在 Mac 分发说明维护，此处只摘要和引用，不追加迭代流水。
