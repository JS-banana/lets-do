# M0 执行与验收契约

Mac 主应用的系统提醒事项互操作单独按[提醒事项方案](MAC-REMINDERS.md)验收。

## 当前范围

M0 验证 Mac 上的任务捕获、编辑、日期安排与系统 Widget。A／B／C／D 必需矩阵与冻结条件全部通过后，才可称 M0 完成。当前唯一持久化实现为共享 Core Data／TaskStore。

任务语义、平台导航和 Widget 布局见 [产品与界面设计](PRODUCT-DESIGN.md)。M0 不扩展分享扩展、提醒／重复、全局快捷键、完整清单分类、附件／子任务、地图／参会人／外部日历或两周试用。

Mac 配置与 scheme 见[开发说明](DEVELOPMENT.md#配置与-scheme)，MacDistribution 单库、权限及系统验收见 [Mac 分发说明](MAC-DISTRIBUTION.md)，同候选构建、草稿与公开流程见[发布说明](RELEASING.md)。

全部自动运行使用新的 `-M0Run` 隔离空间，不触碰个人任务库或手工库。设备、授权或人工条件缺失时明确待验，实机结论须有运行记录。

## 数据规则

以下是实现必须保持、并须经设备矩阵确认的约束，不是已全部通过的声明。主要入口为 [TaskStore](../Shared/TaskStore.swift)、[StoreSession](../Shared/StoreSession.swift) 与 [TaskIntents](../Shared/TaskIntents.swift)。

- **唯一事实源与提交**：所有任务入口复用 TaskStore，本机事务提交后才反馈成功；业务 UUID 幂等，只更新实际修改字段。标题、初始正文／格式及计划在同一事务创建，不另建可写快照。完成动作设置目标状态，重复完成不反转，但不能据此声称已做请求去重。
- **正文分支**：正文及格式追加不可变版本，保留版本 UUID、父 ID 和全部分支，版本指针不是唯一备份；恢复旧文字也追加版本。仅改标题须保留已有正文版本，不逐字产生已提交版本。
- **删除与重复记录**：删除采用 tombstone，普通编辑不得清除或复活；恢复须显式操作，不自动清理任务、正文或历史。同任务 UUID 的物理重复按各自的 `recordKey` 稳定选主，只展示一个业务任务；任一副本 tombstone 生效，写动作更新全部副本。不按标题去重。正文按版本 UUID 归并，同版本 UUID 的文字、格式或父关系不同则保留原记录并报错；物理清理须另有数据安全证据与迁移设计。
- **原子计划**：类型、起止、时区等计划信息存为一个 JSON 标量，写入与读回均校验，避免字段合并拼出反转／混合区间。并发改期允许选取一个完整有效计划，不承诺保留两个日期意图；真机必须验证。日期使用半开区间，界面结束日包含当天；零点、跨周／年与夏令时按共享规则。`week` 是该周待安排，不占七天全天日程；安排到具体日修改原 UUID，不复制任务。新增编码不承诺旧二进制可读，读失败保留原库；既有计划、旧草稿与备份须兼容。
- **本机草稿**：原子文件属于当前任务库的命名空间，保留任务 ID、草稿 ID、基线父版本、文字、格式及捕获计划；任务仍以 TaskStore 为准。重启可恢复；捕获复用草稿业务 UUID，正文保存以同草稿 ID 幂等追加，事务成功后再清理，清理失败保留并按 UUID 核对。任务更新时保留正在输入的草稿，关闭详情前核实落盘；失败保留编辑器与错误，旧详情不能向新库写入。
- **进程与模型**：主应用负责建库／迁移。扩展只打开已核验的现有库，独立消费历史。共享会话、模型租约及写锁均保留；时间线绑定命名空间，切库旧动作、缺库或模型不兼容均拒写并提示打开主应用。模型版本进入工程、导出与证据；启动／迁移失败保留原库和草稿，不删库重建、不静默落入默认库。
- **Widget 读安全**：会话不可用时隐藏任务并提示打开应用。读取失败须与空任务状态区分。主应用与 Widget 的显示读取按任务隔离：某条任务的记录缺字段、正文同版本冲突、父版本成环（含跨任务的环）或计划无法解码时，只略过该任务；正文缺任务 UUID 时按关系归属，无法归属的正文不计入任务。主应用与 Widget 都提示略过数量，不显示成没有安排；记录本身不修改、不删除，这些任务的捕获草稿保留在磁盘不恢复，指向它们的链接在恢复可读后再打开。会话与模型门禁错误仍整体拒绝；MacDistribution 启动时若没有任何可读任务而存在不可读任务，仍按启动失败处理并阻断扩展。任务 JSON 导出和提醒事项回写使用严格读取，任一记录异常即停止。
- **迁移与恢复**：最低验证包括两个独立 TaskStore 实例访问同一隔离库、写锁争用可见失败且无部分提交、扩展遇缺库／不兼容模型保留文件并拒绝建库写入；真实扩展在主应用迁移模型时启动，仍需设备验证。主应用负责 Core Data V1 到 V2 的模型迁移，保留旧纯文本正文。任务 JSON 从一致读取视图导出，拒绝不完整备份；恢复仅限空的隔离本地库，禁止默认覆盖同 ID 或由扩展恢复。任务 JSON 不包含完整物理记录身份、草稿与持久化历史。
- **隐私**：不宣称天然端到端加密。日志只记录动作／对象 ID、进程、耗时与错误类别，不记录标题、正文或账户原始标识；导出与截图只用合成隔离数据。私有绝对路径、个人签名值、原始测试标识、数据库和原型截图不进入公开文档。

## A／B／C／D 必需矩阵

### A 捕获与编辑

工程自检：[TaskStoreTests](../Tests/TaskStoreTests.swift) 覆盖提交、草稿重启、分支、重复记录、并发改期、删除、备份恢复及门禁。必需运行：

1. 在 Mac 的隔离库创建任务，退出再打开，核对 UUID、标题、安排与草稿。
2. 基于同一父正文保存不同文字，核对分支均可恢复。基于旧快照并发改期须得到完整有效计划。
3. 回收任务后提交旧编辑，普通编辑不得复活。另行验证显式恢复。
4. 导出并恢复到新空隔离本地库，逐字段核对。

通过标准为重启后数据保留、全部正文分支可恢复、错误可见。证据包含系统、构建与模型版本、动作 UUID、导出及日志。

### B Mac 月历

工程自检：[SchedulingTests](../Tests/SchedulingTests.swift)、[CalendarPlanningTests](../Tests/CalendarPlanningTests.swift) 与 [WeekTaskOverviewTests](../Tests/WeekTaskOverviewTests.swift)。必需原生运行：

1. 在隔离库中准备样例，覆盖上月跨入、跨周／年、零点结束、同日满格及未安排；核对周一开始、标题、跨周条、每天不同任务的 `+N`。任务点击定位原 UUID，日期／溢出打开当天完整任务并能定位原项。
2. 在待办详情为未安排任务设置日期，拖动周待安排任务及跨日条到新日期，整条开始日对齐落点，保持 UUID 与原跨度，截止日期不参与移动；重启复核持久化。
3. 连续翻月、选择与拖动，核对文字可读、响应与空间不足时的浏览；保存原生窗口、操作、导出和可获得的性能观察。

算法测试不代替真实手势、布局和响应证据；固定样例不等于大数据性能验收。

### C 系统 Widget

工程自检为共享库、锁、会话门禁的集成测试与分发配置编译。在真实 Mac 上安装系统 Widget，分别覆盖主应用前台、关窗仍运行、真正退出三种状态。

1. 从同设备共享库显示隔离任务；系统 gallery、实际放置及点击分别留证，不以 App 预览代替系统宿主。
2. 点击完成并连点，数据库只设置目标状态。记录 Intent 的真实进程与 PID、动作 ID、本机提交及 Widget 与应用的实际显示。
3. 主应用退出时验证扩展本地提交。再打开主应用，核对同一任务的完成状态。
4. 已删除任务、旧时间线、切库、缺库及模型不兼容均不得误写、建空库或迁移。

当前完成操作由普通 AppIntent 在扩展中写入共享库。

| 观察 | 判定与动作 |
|---|---|
| 本机已提交，Widget 和重启后的主应用均能读回同一 UUID 的完成状态 | 记录主应用状态、运行进程和系统显示结果 |
| 只有动画未提交、重复反转、过期无提示、重启后状态未保留 | 本轮失败，修复既定路径并重跑，不降低标准 |
| 丢正文分支、模型不匹配仍写入、迁移失败删库 | 安全失败，保留证据与原库，停止危险路径，先修复 |

### D Mac 安装与系统接入

1. 用 `Todo.xcodeproj` 的共享 scheme 编译主应用与 Widget，执行项目测试，命令见[检查与构建](DEVELOPMENT.md#检查与构建)。
2. 安装 MacDistribution 候选，核对冷启、重启保留、系统组件图库与容器权限。操作步骤见 [Mac 分发说明](MAC-DISTRIBUTION.md#候选资产验收)。
3. 记录 OS／SDK／Swift／Xcode／设备、包与模型版本、实际签名方法及容器访问结果。敏感原值只留私有证据。
4. 部署下限、编译范围和实测支持矩阵分别记录。

## 冻结与证据准则

| 冻结项 | 必需依据 |
|---|---|
| 唯一持久化 | A／C 的共享写入、正文分支与导出恢复 |
| Widget 执行 | C 的主应用各运行状态、Intent 进程、提交结果及系统时间线 |
| 数据安全 | 测试与 A／C 的重启、删除、会话与模型门禁。写入或升级失败时保留任务库与草稿 |
| 支持矩阵 | D 的真实系统、包与必需 API 证据；无设备证据的编译下限只称候选，不扩大支持结论 |
| 签名与能力 | D 的分发包签名、entitlement 与实际容器访问记录 |

### 本机性能

- 以动作 UUID 关联本机事务提交、Widget 读取及实际显示，分别记录时间。
- 本地保存目标 **P95 ≤ 100 ms**，Widget 本地写入目标 **≤ 1 秒**。从业务写入／锁定前至持久化 `save` 返回计时，UI 反馈、系统 Widget 刷新另计。记录设备／OS、冷热、数据量、样本数、原始耗时和构建配置，给出中位数、P95、最大值，不混合条件求分位数。
- M0 先留关键路径基线；10,000 条历史／500 活跃任务的大数据性能是后续验收，不能用固定月历样例或少数快样本代替。

### 留证与维护

每次检查记录真实命令、退出状态、源码提交与逐文件 SHA256、日志 SHA256，以及包／资产、系统、模型和隔离空间。源码在检查期间变化不能记为稳定版本；不同源码、配置、签名包和阶段不得拼成一次完整验收。最终发行绑定同一候选 manifest／归档散列，公开不得重建、重签或重传替代资产。

构建、XCTest、签名、原生 GUI、系统 Widget 和系统提醒事项互操作分别记结论。原生 GUI 须有实际操作、截图与数据读回；当前没有 XCUITest 目标，GUI 记录不计入 XCTest 数量。刷新请求、动画、App 预览、单进程测试和双架构编译都不是系统运行证明。

报告、原始日志、`.xcresult`、合成截图与导出留在被忽略的 `.build/`；交接时说明材料是否实际随交付保留。成功、失败与被后续修复的旧记录均保持原义，修复补新证据，不覆盖失败历史。公开页只写脱敏摘要和覆盖边界，不用不可访问的私有路径作依赖。

日志格式 2：`actionID` 是一次业务动作，`subjectID` 是任务／正文版本，`eventID` 是日志行；事务作者带进程和动作 ID，Intent 成功复用动作 ID。历史格式 1 的 `actionID` 是业务对象 ID，保留并注明，不与格式 2 混读。

后续将新证据的身份、实际覆盖、待验条件与下一步集中更新本契约下节；Mac 同资产结果在 Mac 分发说明维护，此处只摘要和引用，不追加迭代流水。
